# Historical Analysis and Backtesting

## Current Availability

The authenticated owner-scoped historical-analysis run API, canonical dataset-manifest persistence, bounded worker, immutable report persistence, pure deterministic fixed-preset and configurable-exit simulation engines, authenticated browser request/lifecycle/report flow, strategy builder, and configurable report presentation are Implemented. The existing fixed-preset API and worker scenarios are Verified through the latest full isolated E2E pass; the configurable execution path, strategy builder, and configurable report presentation are Unverified until a maintainer-requested pass. Production-provider and broader runtime behavior remain separately scoped. The API stores a bounded request and strategy snapshot plus lifecycle metadata for queued, running, succeeded, failed, or cancelled work. The separate database worker validates canonical coverage, dispatches the pinned engine version from immutable snapshots without contacting Binance, and publishes one immutable report plus trades and equity points per successful run. The browser selects only server-returned markets and preset versions, makes server-controlled assumptions available from the setup Info dialog, polls visible selected work, and presents only server-provided report data.

## Current Run Contract

Run creation supports controlled Binance Spot markets, active fixed preset code/version pairs, `1h` and `4h` preset timeframes, and explicit UTC start-inclusive/end-exclusive ranges of 7 through 90 days. The server resolves the SMA `sma_close_v1` or RSI `rsi_wilder_close_v1` calculation snapshot and the required 200- or 15-candle warm-up boundary. An omitted strategy is normalized to `legacy_fixed_horizon_v1` with the original six-candle semantics. An explicit strategy is normalized to `configurable_exit_v1`, long direction, and server-validated exit rules; the configuration endpoint advertises this supported execution path. Dataset preparation then reads only current canonical rows for the exact `[warmup_start, analysis_end)` window, requires complete contiguous coverage, snapshots full values and source metadata, and stores a deterministic `historical_dataset_fingerprint_v1`. The visible analysis range remains distinct from warm-up data.

Users can create, list, inspect, and cancel only their own runs. Creation requires CSRF and a UUID idempotency key, uses bounded process-local rate limits, and allows at most two queued or running runs per user. A queued cancellation is immediate; a running cancellation is recorded for the worker to acknowledge at safe stage boundaries. Responses contain safe snapshots, progress, timestamps, and failure categories only. No run state creates live signal occurrences, alerts, subscriptions, Telegram jobs, browser notifications, or trading actions.

## Immutable Strategy Contract

Every run stores a canonical strategy snapshot and lowercase SHA-256 fingerprint. The snapshot pins the fixed entry preset code/version, timeframe, signal direction, calculation version, position direction, and normalized exit rules. Configurable strategies support long direction only, at most four rules, exactly one required `max_holding_candles` rule, and at most one each of take-profit percentage, stop-loss percentage, and RSI threshold-cross exits. TP is limited to `0.01` through `1000` percent, SL to `0.01` through less than `100` percent, RSI thresholds to greater than `0` and less than `100`, and holding periods to `1..2200` candles. Decimal values remain strings in the API and are normalized with `Decimal` before persistence; arbitrary expressions and user code are never accepted.

The server publishes these limits and the deterministic same-candle priority (`stop_loss_percent`, `take_profit_percent`, `rsi_threshold_cross`, `max_holding_candles`) through the configuration endpoint. The browser capability flag is true for this supported execution path. Safe strategy validation errors expose only field paths and stable codes. Idempotent replay comparison includes the normalized strategy fingerprint, so reusing a key with a different strategy returns a conflict.

## Deterministic Fixed-Preset Simulation Engine

`freecoinalert_api.historical_analysis.engine` is a provider-neutral, database-independent pure module. It creates no SQLAlchemy session, file, process, thread, network call, worker, or log side effect. Its published versions are `historical_fixed_preset_v1` and `fixed_horizon_v1`; changing signal timing, execution, costs, sizing, holding period, overlap handling, formulas, or metrics requires a new version.

The engine accepts one ready dataset manifest, ordered immutable candle snapshots, one pinned preset snapshot, its pinned calculation version, and the explicit analysis range. It supports all eight version-1 SMA 200 and Wilder RSI 14 presets on `1h` and `4h`. It recalculates from the supplied candles rather than reusing `signal_events`, so the result is reproducible from the selected dataset.

The fixed-horizon assumptions are: 10,000 quote units of initial equity; a signal is known at the confirmed signal-candle close; entry is the next candle open; the entry candle is held as candle one of six; exit is the sixth held candle close; cross-above is long and cross-below is synthetic short; one position uses 100% of current equity; overlapping signals are ignored; entry and exit slippage are each 5 basis points adverse; fees are 10 basis points of allocated equity per side; there is no stop loss, take profit, or early exit; incomplete forward windows are not opened; later trades compound prior net closing equity; and synthetic-short net loss is capped at 100% of allocated equity. A synthetic short is analytical inverse exposure, not an executable Binance Spot trade and does not model borrowing, margin, funding, liquidation, leverage, or derivatives.

For a signal at candle index `i`, `entry_index = i + 1` and `exit_index = entry_index + 5`. The signal reads only data through `i.close_time`, entry reads only the next candle open, and exit reads only the sixth held candle close. Warm-up candles initialize the calculation and prior relation but cannot create signals, trades, or visible equity points. A signal is not opened unless both entry and exit are inside `[analysis_start, analysis_end)`. A scheduled exit at a candle close is processed before a new signal known at that same close, so the next candle may be eligible for a new entry.

The engine reuses `sma_close_v1`, `rsi_wilder_close_v1`, and the equality-aware crossing helper used by live evaluation. It validates market/timeframe identity, UTC boundaries, completeness, positive finite prices, exact continuity, revisions, source metadata, and resource limits before calculation. Typed outcomes are `success`, `insufficient_history`, `invalid_input`, `gap_detected`, `unsupported_preset`, `unsupported_calculation_version`, `unsupported_engine_version`, and `unsupported_assumption_version`; non-success outcomes contain no partial trades or equity series.

Successful results contain immutable hypothetical trades, one net mark-to-market equity point per visible analysis candle close, and summary metrics for signal/trade counts, gross and net return, maximum drawdown, win rate, and profit factor. Zero-trade ranges succeed with `win_rate` and `profit_factor` undefined as `no_trades`; profit factor is undefined as `no_losing_trades` when gains exist without losses and is zero when losses exist without gains. Displayed Decimal values are normalized strings quantized half-even to eight places. The result fingerprint uses `historical_simulation_result_v1` and includes the dataset fingerprint, pinned versions, range, assumptions, every trade, every equity point, and every summary/undefined reason. Result metadata states that the output is a historical hypothetical simulation, not financial advice, not a prediction, not a delivery or profit guarantee, and that synthetic short results are not executable Binance Spot trades.

## Configurable Exit Simulation Engine

`freecoinalert_api.historical_analysis.configurable_engine` is a separate long-only path named `historical_configurable_exit_v1` with assumptions version `configurable_exit_v1`. It preserves the fixed engine and its `historical_simulation_result_v1` serialization and fingerprint byte-for-byte. The configurable result uses `historical_simulation_result_v2` and includes the immutable strategy version, strategy fingerprint, canonical strategy snapshot, exit metadata, and the same result metrics and equity series.

The entry signal keeps the selected preset's direction, but every configurable position is long. A confirmed signal schedules entry at the next candle open. The full configured maximum-holding window must be inside the analysis range before a signal is admitted; overlapping signals remain ignored and only one position uses all current equity. The entry candle is holding candle one. On each holding candle, the engine evaluates exits in this fixed order: stop loss, take profit, RSI threshold cross, then maximum holding. Stop loss uses the level `entry_raw * (1 - percent / 100)`; a candle opening below the level exits at its open with basis `gap_open`, otherwise a low touching the level exits at the level with basis `stop_loss_level`. Take profit uses `entry_raw * (1 + percent / 100)` and a high touching the level exits at that level with basis `take_profit_level`. If several rules could trigger in one candle, stop loss wins. RSI exits use the existing Wilder RSI 14 close series and equality-aware crossing helper on confirmed closes, with basis `confirmed_candle_close`. Maximum holding exits at the close of the configured Nth candle with the same basis.

Configurable fills use exact Decimal arithmetic: entry is `entry_raw * (1 + entry_slippage_rate)`, exit is `exit_raw * (1 - exit_slippage_rate)`, gross return is `exit_raw / entry_raw - 1`, and net return is `exit_fill / entry_fill - 1 - entry_fee - exit_fee`, floored at negative 100 percent. Closing equity compounds into the next position. Each trade persists `exit_reason`, `exit_price_basis`, and the exact `exit_rule_snapshot`. Legacy trade rows are backfilled as maximum-holding exits at confirmed candle close with a six-candle rule snapshot; their historical prices, metrics, v1 serialization, and v1 fingerprint do not change.

The platform stores canonical closed candles, derives UTC-aligned `1h`/`4h` candles, versions server-controlled preset calculations, and creates immutable signal occurrences. ## Worker and Report Boundary

`freecoinalert_api.historical_analysis.worker` is a separately runnable database worker. It claims due queued rows with `FOR UPDATE SKIP LOCKED`, runs one simulation at a time by default, and never contacts Binance or another provider. A claim records `running`, `preparing_dataset`, 10 percent, a worker identifier, and an incremented attempt count. Stale running claims are safely requeued with bounded delays of 5 seconds, 30 seconds, or 2 minutes, or fail with `historical_analysis_attempts_exhausted`; database/transient orchestration failures are the only retried category.

The worker prepares or reuses one immutable dataset, validates it immediately before simulation, loads at most 2,500 snapshot candles into memory, releases database locks, and dispatches synchronously to `simulate_fixed_preset` or `simulate_configurable_exit` from the persisted simulation version. It checks cancellation before preparation, after preparation, before simulation, and after simulation. Before publication it locks the run and dataset, takes share locks on the referenced canonical candle rows, revalidates the dataset fingerprint, computes exit-reason counts from the complete result, and atomically inserts the report's immutable strategy snapshot/fingerprint, complete immutable trade rows including exit metadata, complete ordered equity points, and the `succeeded` transition. A stale or mismatched dataset fails safely and is never rebuilt under the same run. Repeated publication with the same result fingerprint is idempotent; a different fingerprint fails with `historical_analysis_result_conflict`.

Reports persist schema-versioned market, preset, strategy, coverage, and assumptions snapshots, strategy/result/dataset fingerprints, engine/calculation/assumption versions, all summary metrics and undefined reasons, publication-time exit-reason counts, safety disclosures, immutable trades with exit metadata, and one equity point per visible analysis candle. Legacy reports use the fixed-horizon six-candle and confirmed-close strategy mapping; new reports copy the immutable run strategy rather than reading a mutable preset catalogue. The explicit `analysis:cleanup` command deletes only terminal runs older than `HISTORICAL_ANALYSIS_RETENTION_DAYS`, oldest first, up to `HISTORICAL_ANALYSIS_CLEANUP_BATCH_SIZE`; it does not run as a scheduler and never deletes queued or running work.

The isolated E2E overlay seeds fixed canonical history after migration and provides an internal control service for already registered owner fixtures. Its versioned manifest names positive, negative, zero-trade, paginated, and missing-coverage scenarios with fixed UTC ranges inside the API limits; the first four use deterministic symbol-specific candle shapes for the required report semantics, while the missing-coverage scenario uses the normal seeded history with a failed dataset manifest. The control service prepares datasets for the real worker, gates before claim and after claim for queued/running cancellation, and exposes only bounded owner-scoped signal invalidation for recovery coverage. Success and failure transitions therefore come from the real historical-analysis worker; the browser consumes server-provided decimal, UTC, coverage, assumption, disclosure, and fingerprint values without recalculation. The control service uses the existing repositories and lifecycle services, creates no users, bypasses no ownership checks, and is not mounted in the public API. E2E historical analysis remains provider-neutral and does not query Binance.

## Data and Strategy Version Requirements

Results must identify data source/coverage, exchange, market type, symbol, timeframe, UTC range, canonical candle revisions, preset and calculation version, and missing-data treatment. A published preset version must never be silently reinterpreted.

## Bias and Execution Assumptions

The fixed simulator prevents look-ahead bias and defines entry timing, execution price, exit, stop loss, take profit, duration, fees, slippage, sizing, and treatment of gaps/corrections. A signal alone is not a win-rate or profit claim.

## Required Result Disclosure

The authenticated browser presentation discloses assumptions, date range, sample size, fees, slippage, the immutable strategy and exit rules, persisted exit-reason counts, data source, and limitations, and does not present analysis as financial advice or a guarantee.

## Browser Presentation Boundary

The authenticated `/historical-analysis` route renders a guided flow with `Choose inputs`, `Run analysis`, and `Results` steps inside the responsive dashboard shell. The setup view keeps the primary choices concise and makes assumptions, safety limits, and data behavior available from an Info dialog. It uses native credentialed Fetch with the existing CSRF token for configuration, owner-scoped run creation/list/detail/cancellation, report, trade, and equity endpoints. A review dialog creates one UUID idempotency key and reuses it for an ambiguous retry; no optimistic run is shown and the key is kept in memory only. Previous runs remain owner-scoped, with a fixed desktop side panel and a mobile Sheet that preserves selection and opaque cursors. Selected queued/running runs are polled every five seconds while the document is visible, with polling paused while hidden and resumed immediately when visible. The browser E2E suite also covers reload/navigation during pending lifecycle states and safe session/provider/live-feed recovery through the normal contracts.

The browser formats server-provided decimal strings and timestamps for display, renders the server's at-most-200-point equity preview through the repository-owned shadcn ChartContainer/Recharts composition, and presents report values to two decimal places without changing the underlying server strings. Results use three focused tabs: Overview, Hypothetical trades, and Methodology. Overview contains the compact signal/date context, KPI cards, an immutable strategy summary, an optional exact-version `Monitor this entry` card, persisted exit-reason breakdown, a complete bounded contiguous stored-candle preview, hypothetical buy/sell markers, and equity progression chart; it has no separate equity-data tab or UTC candle-close table. The monitor card reuses the owner-scoped signal-subscription and Telegram-delivery contracts, confirms mutations, and states that only the entry condition is live-monitored. The candle preview retains adjacent source candles and marker anchors and is rendered through TradingView Lightweight Charts with normal pan/zoom inspection. Buy and sell markers are presentation labels for hypothetical long and synthetic-short entry/exit points, never live orders. Exit markers and the trade table display only server-provided reason, price-basis, and rule metadata; chart tooltips do not invent intrabar timestamps. Synthetic-short disclosure is shown only when the stored strategy uses that direction. The browser loads full immutable trades only when Hypothetical trades is activated; the owner-scoped full-equity endpoint remains available to API clients but is not loaded by this presentation. The browser converts exact decimal strings to finite plotting numbers only; it does not recalculate, normalize, interpolate, or change server-selected previews. The browser does not calculate indicators, metrics, drawdown, equity, exit counts, or trade outcomes. Reports are labelled historical hypothetical simulations and remain separate from signal occurrences, alerts, sound, Telegram delivery, provider calls, recommendations, and financial advice.
