# Browser E2E Coverage

## Purpose

This matrix owns the current browser-journey coverage for authentication, the dashboard shell, Telegram, one-time price alerts, preset signals, historical analysis, recovery, responsive workflows, and accessibility. It records the user-visible action or state, the specification that exercises it, and the setup boundary used by that specification. `Implemented / Verified` means the journey is present in the repository and passed the maintainer-requested full isolated E2E pass; production-provider and broader runtime behavior remain separately scoped.

The suite uses the real web application and API over the isolated Compose network. Authentication tests create accounts through the UI. Feature tests may create the owner through the normal authenticated API request context, then use a real browser session. Provider events and Telegram outcomes come from the internal provider simulator. The guarded E2E control service provides the versioned historical scenario manifest, real-worker gates, Telegram-link expiry, high-volume pagination fixtures, and owner-scoped signal invalidation; it does not create users or replace ordinary owner mutations. Browser reports and charts consume server values without recalculating them.

## Combinatorial exclusions

The matrix covers each route, action, lifecycle state, recovery boundary, mobile workflow, and stable accessibility state at least once. Only redundant cross-products are excluded:

| Excluded combination | Reason | Status |
| --- | --- | --- |
| Every historical scenario crossed with every market, preset, viewport, tab, provider outcome, and auth/recovery state | The named scenarios cover the distinct report semantics; multiplying independent axes would repeat the same contract without increasing coverage. | Not applicable |
| Every Telegram outcome crossed with every unrelated route and every mobile dialog | Telegram provider outcomes are covered on `/telegram`; route-specific delivery readiness remains covered by the preset and alert journeys. | Not applicable |
| Every provider disconnect/reconnect or SSE reset crossed with every pagination and report combination | Provider and feed recovery semantics are covered once per affected boundary; report pagination has its own deterministic scenario. | Not applicable |
| Visual snapshots, load/performance, full Firefox/WebKit, production providers, CI scheduling, and browser-side calculation checks | Outside the current browser-journey scope. | Not applicable |
| Blanket accessibility rule exclusions | Not excluded. Serious/critical violations fail; any future exact rule/selector exclusion requires a documented limitation, owner, and removal condition in this document. | Not applicable |
